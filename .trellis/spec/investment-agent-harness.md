# 投资 Agent Harness 共享规格

## 工作流主线

所有非平凡工作应按以下顺序处理：

```text
需求讨论
  -> 文档生成
  -> Figma 原型确认（界面类需求）
  -> SPEC / RFC / ADR（平台、架构或跨阶段变化）
  -> roadmap 拆解
  -> sprint 排期
  -> 实现
  -> 自动测试
  -> dashboard / CI 证据
  -> Finish 复盘
  -> 经验回写
```

## 投资安全约束

- 默认不启用实盘自动交易。
- 没有回测、影子盘和人工审批，不得晋升交易相关 skill。
- 任何影响账户风险的变更都必须有回滚标准。
- 任何收益结论都必须区分基准、策略、Agent 和用户执行影响。

## 原型约束

- 涉及控制台、盯盘、告警、分析、复盘、审批队列的需求，开发前必须完成 Figma 原型确认。
- 原型确认改变范围时，先回写需求，再排期开发。

## 验证约束

- 每个任务都要声明验证方式。
- 自动测试和 CI 是默认门禁。
- dashboard 是状态可视化证据，不替代测试。
