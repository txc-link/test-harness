# 投资 Agent Harness 可视化实施说明

本文面向“最强投资 Agent”的工程要求，说明当前 Harness 可视化如何支撑需求拆解、开发排期、测试门禁、复盘和自我进化治理。

## 目标

本项目的可视化不是普通项目看板，而是投资 Agent 的工程控制面板。它需要回答四类问题：

1. 大需求是否已经被拆成可交付的小任务。
2. 哪些任务正在开发，哪些任务已经通过测试。
3. 哪些任务因为投资风险、影子盘、人工审批或回滚方案缺失而被门禁阻塞。
4. 后续复盘和自我进化是否能追溯到明确的需求、任务和验证证据。

## 当前状态模型

面板按以下链路聚合仓库内的 Harness 产物：

```text
需求文档
  -> 路线图
  -> Sprint 计划
  -> 任务
  -> 质量门禁
  -> 测试 / 评审 / 发布证据
```

状态定义如下：

- `待拆解`：需求已经进入 `docs/requirements/`，但还没有路线图。
- `待开发`：任务已拆解，但还没有进入 sprint，也没有足够执行证据。
- `开发中`：任务已进入 sprint，但仍有未完成门禁。
- `测试完成`：任务声明的门禁均已有证据。
- `门禁受阻`：高风险门禁缺失，需要补充回测、影子盘、人工审批或回滚方案。

## 投资 Agent 特有门禁

投资系统不能只看“代码是否能跑”，还要看“是否值得被信任”。因此面板会把以下门禁作为一等状态：

- `unit_tests`：基础逻辑、CLI 和 schema 测试。
- `integration_tests`：跨模块流程测试。
- `data_quality`：数据质量和评估规格。
- `backtest`：策略、信号和 skill 变更的回测证据。
- `shadow_live`：进入真实使用前的影子盘观察。
- `human_approval`：影响真实账户、风险或自动晋升时的人工确认。
- `rollback_plan`：出现异常时的回滚方案。

## 生成方式

在项目根目录执行：

```powershell
python -m harness_engine.cli dashboard
```

命令会生成两个产物：

- `docs/dashboard/status.json`：结构化状态，可供 CI、GitHub Pages、外部监控或后续 MCP 工具读取。
- `docs/dashboard/index.html`：静态可视化面板，可直接用浏览器打开。

## 当前验证口径

当前样例数据应至少覆盖以下状态，证明面板可以表达完整工作流：

- 有需求已经完成拆解。
- 有需求仍处于待拆解。
- 有任务进入开发中。
- 有任务已经测试完成。
- 有任务因高风险门禁缺失而受阻。

这组状态能模拟真实项目里“一部分需求正在开发，一部分需求已测试完成，一部分需要补验证”的工作面。

## GitHub 提交追踪

面板会读取本地 Git 仓库最近提交，并根据 `remote.origin.url` 生成 GitHub commit 链接。这样每次需求拆解、开发、测试和文档变更，都能在面板中追溯到对应提交。

当前实现范围：

- 读取最近 8 条提交。
- 展示短 SHA、提交标题、作者和提交时间。
- 当 remote 指向 GitHub 时，自动生成提交链接。

后续增强方向：

- 接入 GitHub API，展示 PR、review、check run 和 release 状态。
- 把每个任务和提交通过 ticket id 或需求 id 自动关联。
- 在面板中标记“已提交但 CI 未通过”的工作项。

## Figma 原型验证

前端类需求应纳入 Figma 原型快速验证流程。详细流程见 `docs/FIGMA_PROTOTYPE_WORKFLOW.md`。

简化口径：

```text
需求 -> Figma 原型 -> 人工确认 -> 实现 -> 浏览器截图验证 -> 测试与 CI -> 复盘
```

该流程适用于盯盘面板、告警中心、复盘视图、策略分析页面、人工审批队列和投资 Agent 控制台。

## 后续增强方向

下一阶段建议把静态面板升级为工程控制台：

- 接入 GitHub Actions，把最近一次 CI 结果写入面板顶部。
- 接入 GitHub Projects，把任务状态同步到项目看板。
- 增加 Agent 运行 ledger，展示每次投资分析、信号生成、复盘和 skill 晋升的执行轨迹。
- 增加账户收益、回撤、风险暴露、交易成本和基准对比指标。
- 增加人工审批队列，专门处理真实账户、资金风险和 skill 晋升决策。
